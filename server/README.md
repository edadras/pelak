# سامانه هوشمند پایش تردد شهری

سامانه کامل و تحت وب برای اتصال **تعداد نامحدود دوربین** (دوربین‌های شهری، امنیتی، Axis، Hikvision، Dahua، ONVIF و …)،
**پلاک‌خوانی** خودکار، تشخیص **نوع، رنگ، سرعت و بار خودرو**، شناسایی **پارک حاشیه‌ای و پارک دوبل** و کنترل
**مجاز بودن تردد** هر خودرو بر اساس منطقه شهر، ساعت و روز. رابط کاربری فارسی و راست‌به‌چپ است.

## قابلیت‌ها

| بخش | توضیح |
|---|---|
| پلاک‌خوانی | پلاک‌های ملی و مناطق آزاد با مدل‌های همین مخزن (`model/plateYolo.pt`، `model/CharsYolo.pt`)، رأی‌گیری بین چند فریم، تشخیص نوع پلاک (شخصی، تاکسی، دولتی، انتظامی، عمومی، معلولین) |
| نوع خودرو | سواری، تاکسی، ون، وانت، مینی‌بوس، اتوبوس، کامیونت، کامیون، تریلی، موتورسیکلت (YOLOv8 + اندازه نسبی) |
| سنگین / وانت / بار | برچسب خودروی سنگین و وانت، و تخمین باردار یا بدون بار برای وانت و کامیون |
| رنگ خودرو | ۱۰ رنگ رایج (سفید، مشکی، نقره‌ای، طوسی، قرمز، آبی، …) |
| سرعت | با دو خط کالیبراسیون روی تصویر و فاصله واقعی بین آن‌ها؛ ثبت تخلف سرعت با تلورانس قابل تنظیم |
| پارک | پارک حاشیه‌ای (ناحیه مجاز)، توقف در محل ممنوع، **پارک دوبل** (توقف در مسیر عبور کنار خودروی پارک‌شده در حالی که ترافیک جریان دارد)، خط ویژه اتوبوس |
| قوانین تردد | ممنوعیت بر اساس نوع خودرو، بار، روزهای هفته و بازه‌های ساعتی در هر منطقه؛ طرح ترافیک (نیازمند مجوز)؛ طرح زوج و فرد؛ معافیت دسته‌های پلاک و دارندگان مجوز |
| فهرست پیگیری | هشدار فوری با دیده شدن خودروهای سرقتی یا تحت تعقیب |
| مناطق شهر | رسم محدوده‌ها روی نقشه، اتصال دوربین‌ها و قوانین به آن‌ها |
| پایش زنده | شبکه ۱، ۴، ۹ و ۱۶ تصویری با تحلیل روی تصویر، فید لحظه‌ای رویدادها (WebSocket) |
| داده‌ها | جستجوی تردد با پلاک ناقص، پرونده هر خودرو با مسیر روی نقشه، بررسی و تایید/رد تخلف، اصلاح دستی پلاک، خروجی CSV (اکسل) |
| گزارش‌ها | روند تردد و تخلف، ترکیب خودروها، رنگ، نوع پلاک، توزیع سرعت، پرترددترین دوربین‌ها و مناطق |
| مدیریت | کاربران با سه نقش (مدیر، اپراتور، ناظر)، ثبت رویدادهای مدیریتی، حذف خودکار داده‌های قدیمی، API کامل با مستندات |

## معماری

```
دوربین‌ها (RTSP / HTTP / ONVIF)
        │
┌───────▼────────┐  ┌────────────────┐        ┌─────────────────────────┐
│ Worker 1 (GPU) │  │ Worker N (CPU) │  ...   │ هر worker تا سقف مشخصی    │
│ تشخیص/ردیابی   │  │                │        │ دوربین را «اجاره» می‌کند؛  │
│ پلاک/رنگ/سرعت  │  │                │        │ با خرابی یک سرور، دوربین‌ها│
└───────┬────────┘  └───────┬────────┘        │ خودکار منتقل می‌شوند       │
        │ رویداد + تصویر زنده                   └─────────────────────────┘
┌───────▼──────────────────▼───────┐
│ PostgreSQL  +  Redis  +  فایل تصاویر │
└───────┬──────────────────────────┘
┌───────▼────────┐
│ API + رابط وب   │  ← مرورگر اپراتورها (فارسی، RTL)
└────────────────┘
```

- **API** (`app/main.py`): FastAPI، سرو رابط کاربری، WebSocket رویدادها، استریم MJPEG.
- **Worker** (`app/worker/main.py`): گرفتن تصویر، تحلیل، ذخیره رویداد و تخلف. هر تعداد worker روی هر تعداد سرور.
- **Pipeline** (`app/vision/pipeline.py`): تشخیص خودرو ← ردیابی ← پلاک، نوع، رنگ، بار، سرعت، رفتار پارک.
- **Rules** (`app/core/rules.py`): موتور قوانین تردد (بدون وابستگی به پایگاه داده و دارای تست).

## نصب روی سرور (Docker)

پیش‌نیاز: Linux با Docker و Docker Compose. برای GPU: درایور NVIDIA و nvidia-container-toolkit.

```bash
git clone <repo> pelak && cd pelak/server
cp .env.example .env          # رمزها و SECRET_KEY را حتماً تغییر دهید
docker compose up -d --build
```

سپس مرورگر: `http://<IP-سرور>:8080` — ورود با نام کاربری و رمز تعیین‌شده در `.env` (پیش‌فرض `admin` / `admin123`؛
بلافاصله از منوی کاربر رمز را عوض کنید).

- **افزایش ظرفیت دوربین روی همین سرور:** `docker compose up -d --scale worker=4`
- **GPU:**
  ```bash
  TORCH_INDEX=https://download.pytorch.org/whl/cu121 \
  docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
  ```
- **سرور پردازش اضافه (چندسروره):** روی سرور دوم همین image را اجرا کنید و فقط worker بالا بیاورید، با
  `DATABASE_URL` و `REDIS_URL` که به سرور اصلی اشاره می‌کنند:
  ```bash
  docker run -d --gpus all --name pelak-worker --restart unless-stopped \
    -e DATABASE_URL=postgresql+psycopg2://pelak:<pass>@<main-ip>:5432/pelak \
    -e REDIS_URL=redis://<main-ip>:6379/0 -e DEVICE=cuda -e WORKER_MAX_CAMERAS=32 \
    -v /mnt/pelak-media:/data/media -e MEDIA_DIR=/data/media \
    pelak-server:latest python -m app.worker.main
  ```
  پوشه تصاویر (`MEDIA_DIR`) باید بین سرورها مشترک باشد (NFS یا مشابه). پورت‌های 5432 و 6379 را فقط برای
  سرورهای پردازش باز کنید.
- **شبکه داخلی / بدون اینترنت:** همه کتابخانه‌های رابط کاربری و فونت داخل پروژه هستند. برای نقشه، یک
  tile server داخلی راه‌اندازی و `MAP_TILE_URL` را تنظیم کنید. برای ساخت image پشت آینه رجیستری:
  `BASE_IMAGE=docker.arvancloud.ir/python:3.11-slim-bookworm docker compose build`.
- **HTTPS:** نمونه تنظیمات nginx در `deploy/nginx.conf` (HTTP/2 محدودیت اتصال مرورگر برای تصاویر زنده را هم برطرف می‌کند).

### برآورد سخت‌افزار

اعداد تقریبی هستند و به رزولوشن، تعداد خودرو در تصویر و `PROCESS_FPS` بستگی دارند؛ پیش از خرید با دوربین‌های واقعی خودتان آزمایش کنید.

| پردازنده | دوربین هم‌زمان به ازای هر worker (۶ فریم تحلیلی در ثانیه) |
|---|---|
| CPU ۸ هسته‌ای | ۲ تا ۴ |
| GPU کلاس RTX 3060 / T4 | ۱۶ تا ۲۴ |
| GPU کلاس RTX 4090 / A10 | ۳۲ تا ۴۸ |

«نامحدود» یعنی سقف نرم‌افزاری ندارد: با افزودن worker یا سرور، ظرفیت به صورت خطی بالا می‌رود.

## اتصال دوربین‌ها

در صفحه «دوربین‌ها» برند را انتخاب و IP، نام کاربری و رمز را وارد کنید؛ آدرس استریم خودکار ساخته می‌شود.
با «تست اتصال» یک تصویر نمایش داده می‌شود.

| برند | قالب آدرس ساخته‌شده |
|---|---|
| Axis | `rtsp://user:pass@ip:554/axis-media/media.amp?videocodec=h264&camera=1` |
| Hikvision | `rtsp://user:pass@ip:554/Streaming/Channels/101` (فرعی: `102`) |
| Dahua | `rtsp://user:pass@ip:554/cam/realmonitor?channel=1&subtype=0` |
| Uniview | `rtsp://user:pass@ip:554/unicast/c1/s0/live` |
| Hanwha (Wisenet) | `rtsp://user:pass@ip:554/profile2/media.smp` |
| Bosch | `rtsp://user:pass@ip:554/?inst=1` |
| Vivotek | `rtsp://user:pass@ip:554/live1.sdp` |
| Milesight | `rtsp://user:pass@ip:554/main` |
| ONVIF (سایر برندها) | آدرس از خود دوربین با `GetStreamUri` دریافت می‌شود (پورت HTTP دوربین، معمولاً 80) |
| RTSP / HTTP دستی | هر آدرس دلخواه |
| فایل ویدیو | برای آزمایش؛ از همان صفحه قابل بارگذاری است |

**دوربین‌های Axis:** در تنظیمات دوربین RTSP فعال باشد و یک کاربر با سطح Viewer بسازید.
**توصیه برای پلاک‌خوانی دقیق:** جریان اصلی (main)، زاویه عمودی کمتر از ۳۰ درجه، عرض پلاک در تصویر بیش از ۱۲۰ پیکسل،
شاتر سریع (۱/۱۰۰۰ یا کمتر) و نور مادون قرمز برای شب. برای دوربین‌های پلاک‌خوان نزدیک، در تب «تحلیل» روش
«کل تصویر» را انتخاب کنید.

### نواحی و کالیبراسیون سرعت

در تب «نواحی و کالیبراسیون سرعت» روی تصویر دوربین رسم کنید:

- **پارک حاشیه‌ای مجاز**: خودرویی که بیش از زمان تعیین‌شده متوقف بماند «پارک حاشیه‌ای» ثبت می‌شود (تخلف نیست؛ برای آمار اشغال).
- **توقف ممنوع**: توقف طولانی‌تر از حد مجاز ← تخلف.
- **مسیر عبور**: خودرویی که در این ناحیه متوقف است، کنار آن خودروی پارک‌شده وجود دارد و در همان زمان خودروهای دیگر
  در حال عبورند، **پارک دوبل** ثبت می‌شود. اگر همه خودروها ایستاده‌اند (ترافیک یا چراغ قرمز)، چیزی ثبت نمی‌شود.
- **خط ویژه اتوبوس**: عبور خودروهای غیرمجاز ← تخلف.
- **سرعت**: دو خط عرضی A و B روی جاده رسم و فاصله واقعی آن‌ها را به متر وارد کنید (خط‌کشی‌های منقطع جاده مرجع خوبی هستند).

## قوانین تردد

نمونه‌هایی که با اولین اجرا (به صورت غیرفعال یا قابل ویرایش) ساخته می‌شوند:

- ممنوعیت تردد کامیون و تریلی در محدوده طرح، شنبه تا پنجشنبه ۶ تا ۲۱
- طرح ترافیک: ورود بدون مجوز ۶:۳۰ تا ۱۸ (تاکسی، عمومی، انتظامی، دولتی و معلولین معاف)
- طرح زوج و فرد: پلاک زوج شنبه/دوشنبه/چهارشنبه (ملاک: رقم آخر عدد سه‌رقمی پلاک)
- ممنوعیت وانت باردار در ساعات اوج

مجوزها (طرح ترافیک، زوج و فرد، تردد سنگین، ساکن محدوده) از صفحه «مجوزها و فهرست‌ها» یا با فایل CSV وارد می‌شوند.

## دقت و محدودیت‌ها (مهم)

- **پلاک‌خوانی** با مدل‌های موجود همین مخزن انجام می‌شود؛ دقت آن به زاویه، رزولوشن و نور دوربین وابسته است.
  تصویر پلاک و خودرو کنار هر رویداد ذخیره می‌شود و تصویر شاهد همیشه متعلق به همان پلاک ثبت‌شده است. اپراتور
  می‌تواند تخلف را بررسی، تایید یا رد و پلاک را اصلاح کند.
- **نوع خودرو** از مدل عمومی YOLOv8 (COCO) به‌علاوه اندازه نسبی خودرو در تصویر به دست می‌آید. کلاس‌های
  «وانت» و «باردار/بدون بار» در COCO وجود ندارند و تا زمان آموزش مدل اختصاصی با روش ابتکاری تخمین زده می‌شوند.
  برای دقت بالا مدل اختصاصی آموزش دهید (بخش بعد).
- **سرعت** فقط برای دوربین‌های کالیبره‌شده محاسبه می‌شود و دقت آن به دقت اندازه‌گیری فاصله دو خط بستگی دارد.
  برای استفاده رسمی در جریمه، کالیبراسیون و تاییدیه مرجع ذی‌صلاح لازم است.
- تخلفات به صورت پیش‌فرض در وضعیت «در انتظار بررسی» ثبت می‌شوند تا پیش از هر اقدام، انسان آن‌ها را تایید کند.

### آموزش مدل اختصاصی نوع خودرو و بار

```bash
python tools/export_crops.py --out crops --types pickup light_truck truck car --limit 5000   # برش خودروهای ثبت‌شده
# تصاویر را در پوشه‌های dataset/train/<class> و dataset/val/<class> دسته‌بندی کنید
# (sedan, suv, taxi, van, pickup_empty, pickup_loaded, truck_empty, truck_loaded, ...)
python tools/train_vehicle_attributes.py --data dataset --epochs 40
cp runs/classify/train/weights/best.pt ../model/vehicle_attr.pt   # workers را restart کنید
```

با وجود فایل `model/vehicle_attr.pt` نتیجه این مدل بر روش ابتکاری اولویت می‌گیرد. برای تشخیص دقیق‌تر خودروهای
دور یا کوچک می‌توانید `VEHICLE_MODEL` را روی `yolov8s.pt` یا `yolov8m.pt` بگذارید (روی GPU).

## اجرای توسعه (بدون Docker)

```bash
cd server
python -m venv .venv && . .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
EMBEDDED_WORKER=1 DEMO_VIDEO=lite/data/sample.mp4 uvicorn app.main:app --port 8080
python -m pytest tests        # تست‌ها
```

بدون `DATABASE_URL` از SQLite و بدون `REDIS_URL` از گذرگاه داخلی استفاده می‌شود (مناسب یک سرور و آزمایش).
`tools/simulate_camera.sh` یک فایل ویدیو را به صورت دوربین RTSP منتشر می‌کند.

## API

مستندات تعاملی: `http://<server>:8080/api/docs`. احراز هویت با `POST /api/auth/login` و هدر
`Authorization: Bearer <token>`. نمونه‌ها:

- `GET /api/events?plate=۱۲ب&start=2026-09-20T00:00:00` جستجوی تردد
- `GET /api/vehicles/12B34567` پرونده خودرو
- `GET /api/violations?status=pending` تخلفات در انتظار
- `WS /ws?token=…` رویدادهای لحظه‌ای (`event`، `alert`، `camera_status`)

## امنیت و نگهداری

- `SECRET_KEY`، `ADMIN_PASSWORD` و `POSTGRES_PASSWORD` را در `.env` تغییر دهید؛ سامانه را پشت HTTPS قرار دهید.
- رمز دوربین‌ها در پایگاه داده ذخیره و در API و لاگ‌ها پنهان می‌شود؛ دسترسی به پایگاه داده را محدود کنید.
- پشتیبان‌گیری: `docker compose exec db pg_dump -U pelak pelak > backup.sql` و پوشه تصاویر (volume `media`).
- مدت نگهداری داده‌ها از «تنظیمات و وضعیت» قابل تنظیم است (پیش‌فرض ۹۰ روز).
